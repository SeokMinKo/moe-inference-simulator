Batch and expert reuse

Each request keeps its own KV cache and produces 1,000 tokens. At every decode step the batch processes one token per request. Shared weights and each unique expert are read once per step under ideal within-batch reuse.

For E experts and k active/request: same-set union = k; independent-pick union = ceil[E × (1 − (1 − k/E)batch)]; maximum-spread union = min(E, batch × k). The independent option rounds an expected union up; it is not a measured routing trace or a guaranteed memory bound. Choose maximum spread for the largest union. The modeled union must fit Expert Cache. Extra cache capacity does not automatically raise hit rate.

Predictor time is entered per request and summed across the batch: a conservative serialized assumption. Increase Other resident GB for batch-dependent activations/workspace. Batch changes neither the per-token active parameter count nor the invented quality proxy.

Scope and model size

A synchronous-batch IFP teaching estimate, not a hardware benchmark. W=1 still uses this predictor; it is not a measured standard-MoE baseline. One initially selected set is used for the entire prefill.

Total B = shared B + layers × experts/layer × expert M / 1,000.
Active B substitutes active experts/layer. Approximate linear work/token = 2 × active B billion operations.
Selected GB = layers × unique batch experts × expert M × bits / 8,000. All shared parameters are approximated as active linear weights. KB and GB are decimal; quantization metadata is excluded.

Cache and UFS loading

Miss GB = selected GB × (1 − effective hit/100). Hit is assumed across repicks, not computed from cache capacity or an access trace. The preceding selected set stays cached. A modeled batch union of k out of E experts implies at least max(0, 2 − E/k) × 100% overlap; the input is raised to this floor. Selecting every expert therefore gives 100% later hits.

Load BW = min(effective UFS GB/s, usable DRAM GB/s). UFS is delivered throughput into the final cache for this access pattern, including I/O overhead. A direct destination write is counted once, not added again as a serial DRAM fill. No staging copy, decompression or prefetch during decode is modeled.
Repick pause = miss GB/load BW + batch × predictor seconds/request. DRAM traffic still includes the incoming write.

Independent inputs

The 16-bit KV reference covers K and V across all cached layers. Update this reference or use the separate attention-geometry fields when the architecture changes. Effective KV bytes include the selected KV format and metadata. Weight bits do not set compute precision or KV precision: update effective TOPS separately. Cache capacity affects feasibility; it does not invent a hit-rate improvement. Other resident GB is a manually supplied whole-batch budget: increase it when batch workspace grows. It must include predictor weights/workspace, activations, runtime and any staging buffers.

TTFT and exactly 1,000 outputs

TTFT = other delay + batch × initial predictor/request + initial miss GB/load BW + prefill. Shared weights are already loaded; this is not a full cold-model launch. Queueing, tokenization and delivery are included only to the extent you supply Other TTFT delay.

Prefill = max(2 × active B × batch × prompt / (1,000 × prefill TOPS), (batch-union weight GB + batch × prompt × KV GB/token)/usable DRAM BW). Ideal prompt weight reuse; add the user-supplied KV conversion time below 16 bits. No attention-score FLOPs or attention working traffic are modeled. Long-context TTFT can be substantially underestimated.

Prefill produces output 1. For j=1…999, decode step = max(2 × active B × batch/(1,000 × decode TOPS), batch-union weight GB/DRAM BW) + batch × (prompt+j) × KV GB/token/DRAM BW. KV traffic is a separate attention phase, not hidden under linear compute. Add batch × KV extra μs/token / 10⁶ to each step below 16 bits. Final KV has batch × (prompt+999) positions; output 1,000 is not fed back.

Repicks = floor(999/window), before outputs W+1, 2W+1, …; none after the final output.
Aggregate TPS = (batch × 1,000)/(TTFT + sum of 999 steps + all repick pauses). Aggregate decode-only TPS = (batch × 999)/(steps + repick pauses); TPOT/request = batch / aggregate decode-only TPS. Average TPS/request = aggregate TPS / batch. Batch throughput can improve while each request slows down.

What sets each point’s position?

X = phase operations / phase DRAM bytes. For decode: Fd = 2 × active B × batch × 10⁹ × 999; Dd = 999 steps of batch-union weights and batch KV bytes + repick writes. For prefill: Fp = 2 × active B × batch × 10⁹ × prompt tokens; Dp = batch-union weight bytes + batch prompt KV writes, assuming ideal prompt weight reuse. Initial weight loading is outside both phase intensities.

Blue Y = Fd / (decode seconds + repick pauses) / 10¹² TOPS. It is the rate of the main model’s counted decode work; predictor work is not in Fd, but its waiting time is included. TTFT is excluded.
Red Y = Fp / prefill seconds / 10¹² TOPS. Initial predictor, loading and other delay are excluded. Both points are modeled operation rates, not measured chip utilization.

Each roof = min(phase compute TOPS, usable DRAM GB/s × X / 1,000). Green solid uses Decode TOPS; red dashed uses Prefill TOPS. They coincide when these inputs match. With compute precision, TOPS and bandwidth fixed, model changes do not alter the roof in data coordinates; they may move the points. These are effective limits supplied by the user, not automatically measured hardware peaks.

The Aggregate TPS result below is batch × 1,000 / elapsed time including TTFT. TOPS and TPS are different: doing more operations each second does not necessarily mean generating more tokens each second.

More reuse moves X right; more DRAM traffic per operation moves X left. Bandwidth and compute change time and the roofs, not X at fixed traffic. UFS speed changes decode Y through refill waits; hit/window changes may alter both decode X and Y. Prompt length affects both phase intensities and their times. Prefill sits on its ideal roof only when KV extra time is zero: omitted attention work and runtime overhead can lower actual throughput.

Points are phase averages from simplified linear work and DRAM traffic, not measured kernel performance. The effective roofs assume the precision of the TOPS inputs. Axes auto-scale: compare tick values, not only pixel positions. Points can overlap for identical workloads/rates; hover for values.

Quality is invented, not accuracy

Q = clamp[20 + 50(1 − exp(−total B/20)) + 25(1 − exp(−active B/5)) − penalty, 0, 100]. Penalty = 3 log₂(min(window, 1,000)), or 0 when all experts are selected. Constants are chosen only for teaching; bigger parameter counts do not guarantee better real answers. Quantization quality, predictor error and task difficulty are not modeled. All-expert selection removes this fixed-set penalty, not every source of real quality loss.

KV quantization: capacity and time

The reference input is the full 16-bit K+V payload per token per request. Geometry mode computes 2 × cached layers × KV heads × head dimension × 2 bytes. The layer count here is separate from the number of MoE layers. All cached layers use one geometry and one format in this approximation.

Effective KV KB/token = 16-bit reference × KV bits/16 × (1 + metadata%/100). Metadata applies below 16 bits. Set it for scale/zero-point storage as an estimate; paged allocation, residual FP16 windows, mixed layer formats and MLA are not modeled. Final GB = effective KB × batch × (prompt + 999) / 10⁶.

Extra conversion time is a user-supplied aggregate penalty at the chosen context: batch × processed tokens × μs/token / 10⁶ seconds, below 16 bits only. It is added to prefill and decode. Zero assumes no extra time. Precision alone changes neither hardware TOPS nor the quality proxy. Real speed and accuracy require backend-specific measurements.
